Universal Best Practices — All Roles
1
Supervised Collaboration Model
Don't let AI agents code entire features unattended. Think of AI as a brilliant junior developer: fast, capable, but lacking deep production judgment. Keep oversight at each step.
2
Context is Everything
Always provide architectural context before agentic tasks. Use CLAUDE.md or .cursorrules to encode standards. Include constraints explicitly: performance budgets, security requirements, API contracts.
3
Small Increments + Test After Each
Generate code in small, verifiable increments. Run tests after each AI-generated integration. Never let AI generate hundreds of lines without a verification checkpoint.
4
Prompt Engineering is a Core Skill
Be explicit about what you do NOT want (e.g., "do not add new dependencies"). Specify output format, language version, framework conventions. Define success criteria upfront.
5
Review AI Code as Carefully as Human Code
AI code passes tests and matches conventions — but hides subtle bugs and edge cases. You are accountable for what ships, not the AI.

Measuring Developer Productivity

AI has created a measurement paradox — individual output metrics spike while org-level delivery stays flat. Use a layered approach.

⚠ The Velocity Trap
"Higher velocity doesn't mean more value — if you're shipping more features but they're buggy, AI helped you build the wrong thing faster." Always pair velocity metrics with Change Failure Rate and Rework Rate. — DX Blog via DORA 2025
Reasoning Depth by Tool — Source: Builder.io 2026
What NOT to Measure
These metrics are misleading with AI tools
  • ✗Lines of Code — AI generates verbose code trivially
  • ✗Number of PRs — AI inflates PR count without improving outcomes
  • ✗Commit Frequency — Same issue as PR count
  • ✗Acceptance Rate alone — High acceptance can mean low review standards
  • ✗Self-reported time savings — Developers overestimate by 40–50%

3-Phase Measurement Rollout
Months 1–3
Phase 1: Establish Baselines
  • Instrument DORA metrics BEFORE AI adoption — no baseline = no ROI proof
  • Run developer satisfaction surveys (SPACE Satisfaction dimension)
  • Track PR cycle time and deployment frequency
Months 3–6
Phase 2: Add AI-Specific Tracking
  • Add AI suggestion acceptance rate (from tool APIs)
  • Track Change Failure Rate and Rework Rate changes vs. baseline
  • Survey developers monthly on trust in AI output quality
Months 6+
Phase 3: Outcome Focus
  • Add business outcome metrics (feature adoption, customer defect reports)
  • Track AI Code Retention Rate at 30 and 90 days
  • Instrument security scanning specifically on AI-generated code

8 Key Lessons Across All Companies
1
The Individual-to-Org Gap is Real. Every cross-company study (DORA 2025, Goldman, Google) finds individual gains don't automatically translate to org delivery improvements. Coordination costs and review bottlenecks absorb the gains.
2
Platform Engineering is a Prerequisite. DORA 2025: 90% of high-performing orgs have an internal developer platform. Platform quality is the #1 predictor of AI value. Uber (Michelangelo), Stripe (Toolshed + Blueprints), and Airbnb (AirDev) built platforms before scaling AI.
3
Human Review Remains Non-Negotiable. Stripe ships 1,300 AI PRs/week and reviews every single one. This is the industry's clearest statement that automation volume does not eliminate the need for human oversight.
4
Internal Context > Model Selection. Meta (fine-tuned CodeCompose), Uber (internal context layer with source + Slack + JIRA), and Stripe (Toolshed with 500 internal tools) all found internal grounding outperforms switching to a larger model.
5
Decompose into Discrete, Retryable Steps. Airbnb's migration pipeline, Shopify's Roast, and Stripe's Blueprints independently arrived at the same pattern. Break complex tasks into independently retryable steps with clear success criteria — this is the most transferable engineering pattern.
6
Code Quality Requires Active Defense. GitClear's 211M-line analysis: AI adoption correlates with +48% clone rate, −60% refactoring, +84% code churn. Pair AI generation with AI review (Uber's uReview, Stripe's human review mandate) to counteract drift.
7
Token Costs Scale Faster Than Expected. Uber: costs up 6x since 2024. No company anticipated this growth rate. Instrument AI API costs from day one — token cost governance is now a first-class engineering concern.
8
Adoption Strategy > Tool Choice. Shopify: remove friction (no approval needed). Uber: make AI a CI service, not opt-in. Netflix: deliberate caution. The adoption strategy consistently proved more determinative of realized gains than the specific tool selected.

Block Goose
Open-source autonomous AI agent · Apache 2.0 · Released Jan 28, 2025 · 33K+ stars · 426+ contributors
Open Source Local-first Model agnostic
What It Is
Goose is a fully autonomous, locally-running AI agent framework built in Rust by Block (Square, Cash App). Unlike GitHub Copilot or Cursor — which suggest code — Goose executes tasks end-to-end: install, execute, edit, and test. It was co-developed with Anthropic around the Model Context Protocol and open-sourced after Block deployed it to all 12,000 employees, where engineers report 8–10 hours saved per week.
Architecture
Agent Loop
Planning-first: reasons through a plan before acting. Slower than reactive tools on simple edits; more reliable on complex multi-step workflows.
MCP Extension System
Entire extensibility built on MCP. 3,000+ community servers. Tools, Resources, and Prompts as primitives via JSON-RPC 2.0.
Multi-Agent + Recipes
First-class sub-agent spawning, dynamic model selection, and YAML Recipes for reusable team workflow automation.
How to Use It
CLI (goose)
Terminal-native with session persistence. Describe task in natural language → Goose plans and executes. Best for system-level work, cross-API orchestration, automation scripts.
Desktop App (Electron)
Adds MCP-UI widgets: interactive dashboards, forms, progress bars rendered natively. Unique among CLI agents. Best for teams wanting visual feedback during agent runs.

Stripe Minions
Proprietary autonomous coding agents · Internal only · 1,300+ PRs/week · Built on Goose fork · Feb 2026
Internal only One-shot 1,300 PRs/wk
What It Is
Minions is Stripe's proprietary internal autonomous coding agent — not a product, but infrastructure. Engineers send a Slack message; a PR appears. No human writes code. No back-and-forth during execution. As of February 2026, Minions merges 1,300+ PRs per week — all reviewed by a human before merge — supporting infrastructure that processes $1T+ in annual payment volume. The underlying codebase: hundreds of millions of lines of Ruby with proprietary libraries unknown to any public LLM.
4 Architectural Pillars
1. Devboxes
Every Minion runs in an isolated AWS EC2 VM — same environment human engineers use. Pre-warmed pool spins up in ~10 seconds. Isolated from production and internet. Disposable: failed runs are discarded. Enables safe parallel agent execution.
2. Blueprints
Core execution primitive: interweaves deterministic nodes (git ops, linting, CI steps) with agent loops (LLM reasoning). Deterministic nodes prevent unrecoverable mid-task decisions. "The walls are doing more work than the model."
3. Toolshed (MCP)
Internal MCP server with ~500 curated tools spanning Stripe's internal systems and SaaS. Minions receive scoped subsets — not full access. Capability traded for safety. Modeled on Stripe's compliance philosophy.
4. CI Integration
Runs selective tests from a 3M+ test battery. Two CI rounds maximum — hard cap. Third failure = handoff to human. Empirically found to be the optimal cost/reliability tradeoff.
